# Adoption Plan

Goal: earn legitimate attention from maintainers who need a clean evidence packet for grants, sponsorships, credits, or internal approvals.

## Positioning

OSS Evidence Kit is not a generic GitHub stats badge. It is a reviewer-facing evidence generator.

The strongest audience:

1. solo open-source maintainers;
2. maintainers applying for support programs;
3. maintainers preparing sponsor pages;
4. small teams writing annual OSS impact reports;
5. developer advocates reviewing project health.

## 30-day plan

1. Publish v0.1.0 release.
2. Enable GitHub Pages from `docs/`.
3. Add `--json` output.
4. Add GitHub Action example.
5. Write one practical article: "How to prepare an OSS maintainer evidence report without exaggerating impact."

## 60-day plan

1. Publish to npm.
2. Add report templates for grants, sponsorships, and internal approvals.
3. Add discussion support.
4. Collect feedback through issues.
5. Keep a public changelog with small releases.

## 90-day plan

1. Add package download evidence where public APIs are available.
2. Add dependent-repository evidence.
3. Add a browser preview for generated reports.
4. Create examples for JavaScript, Python, Rust, and docs-only projects.

## Boundaries

No paid stars. No star swaps. No fake testimonials. No scraped private data.
