# Codex for Open Source Application Notes

Date basis: 2026-06-24.

OpenAI's public Codex for Open Source page says maintainers of open-source projects that are widely used or important can apply for support, and the application asks for public repository and maintainer information.

OSS Evidence Kit is designed to help maintainers prepare the public evidence behind such applications. It is not affiliated with OpenAI and cannot guarantee approval.

## Recommended application posture

Use this project only after the repository has real public evidence:

1. a public GitHub repository;
2. a clear MIT license;
3. working CLI with tests and CI;
4. at least one tagged release;
5. documented maintainer role;
6. open and closed issues showing roadmap execution;
7. external usage signals, such as stars, forks, discussions, issues from users, package downloads, blog posts, or dependent projects.

## Why this project can matter

Many maintainers need support programs, credits, and sponsorships, but the review evidence is often scattered. A standard evidence report can reduce review friction and help maintainers explain project importance without exaggeration.

## Short application draft

OSS Evidence Kit is a zero-dependency CLI that helps open-source maintainers generate verifiable public evidence reports from GitHub repositories. It summarizes releases, issues, pull requests, contributors, community files, and adoption signals so maintainers can apply for OSS support programs without fabricating or overstating impact.

## What not to claim

Do not claim:

1. guaranteed OpenAI approval;
2. fake users;
3. bought or exchanged stars;
4. private usage numbers that cannot be verified;
5. affiliation with OpenAI.

## Strongest next evidence

1. Publish a first GitHub release.
2. Add GitHub Pages landing page.
3. Open and close real issues for CLI improvements.
4. Publish the package to npm after the first release is stable.
5. Share with OSS maintainers and ask for real feedback, not star swaps.
